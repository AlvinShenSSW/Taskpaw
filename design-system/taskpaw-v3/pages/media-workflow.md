# 持续影片工作流 · UI / UX 设计

状态：设计稿，待开发。对应 [EPIC](../../../docs/specs/2026-10-19-media-workflow-epic.md) 与 [架构契约](../../../docs/specs/2026-10-19-media-workflow-architecture.md)。本页规定 TaskPaw 内的集成入口和影片工作区，不替代现有任务 / 服务监控。

当前原型：[media-workflow-v3.html](../preview/media-workflow-v3.html)。直接在浏览器打开，无需服务或依赖。壳外演示工具可切换“主控 + 本机 Agent”“远端计算 Agent”与“普通 Agent”；生产安装角色与权限不由这个开关决定。所有影片、演员、地址、硬件报告和目录均为虚构，操作仅更新当前页面内存。

[V1](../preview/media-workflow-v1.html) 与 [V2](../preview/media-workflow-v2.html) 保留为历史设计快照，不是当前集成交付。原型不代表五机调度、安装、配对、硬件探测、NAS 写入、迁移或删除已经实现。

## 现有界面的集成依据

- [App.tsx](../../../taskpaw_v3/ui/src/App.tsx) 已有 TaskPaw V3 顶栏、壳注入固定角色和独立本地 API 健康；Agent / Hub 角色切换只在开发环境显示。
- [HubDashboard.tsx](../../../taskpaw_v3/ui/src/views/HubDashboard.tsx) 的机群 / 管理 / 事件 / 设置保留。[HubAgentManager.tsx](../../../taskpaw_v3/ui/src/components/HubAgentManager.tsx) 已有地址与端口增改、启停和删除；工作流硬件准入及安全退休是后续增量。
- [AgentConsole.tsx](../../../taskpaw_v3/ui/src/views/AgentConsole.tsx) 的本机监控 / 日志 / 设置保留。连接异常时设置仍可访问；现有开发活动和服务监控不会被影片页面取代。

当前 Hub 设备删除会删除部分关联状态、事件与 outbox；新的“移除并保留历史”不能直接复用其破坏性删除语义。后端必须提供独立的安全退休与历史引用契约。

## 设计依据与视觉规范

沿用 TaskPaw 的深色 slate + green 系统，以及已有 LTX 进度原型：背景 `#0B1120`，表面 `#111A2E`，边线 `#263650`，正文 `#F8FAFC`，次级文字 `#A8B5C7`，动作绿 `#22C55E`，信息蓝 `#75D2FA`，待处理琥珀 `#FBC76A`。绿色主按钮使用深色文字 `#06210F`。状态同时使用文字，不能只靠颜色。

使用 ui-ux-pro-max 的 design-system 检索（`desktop media workflow operations dashboard dark slate green human review queue`），以及 UX 检索（键盘、焦点、确认与弹窗）和 html-tailwind 检索（响应式 dashboard / modal / accessible forms）。采用检索中的操作台密度、可见焦点、最小触控区域及减少动态效果；字体保留现有 Fira Sans / Fira Code 和系统中文回退，不引入检索建议的装饰字体，也不覆盖 MASTER。HTML 使用原生 CSS，无远程字体、图片或脚本。

字体层级：页面标题 29px，区块标题 17px，影片名称 14–15px，正文 12–14px，辅助信息 10–12px；数字与耗时使用等宽字体。卡片圆角 12px，控件 8px，主体间距 20–28px。封面全部为原创内联 SVG 几何图，带虚构影片编号，不读取实际封面或演员头像。

## TaskPaw 应用壳与工作区

保留现有 TaskPaw V3 顶栏、品牌、当前安装角色、本地 API 健康与现有角色页面。Windows 主控视图保留机群、管理、事件 / 日志、设置；增加连接本机 Agent 的监控入口，以及“影片工作流”页签。该页签内才出现概览、影片队列、待确认、异常、设备、本机、片库与规则、Mac 信息桥、设置 / 迁移九个内部入口。离开工作区后，原有监控与服务管理继续可用。

影片工作流不另起一套桌面应用，不替代 TaskPaw 原有监控、开发活动、事件和日志。工作区“设备”与 Hub“管理”使用相同注册对象与生命周期；不复制设备记录。主控同机 Agent 是现有五台计算机中的一台，不增加第六个计算节点。

V3 顶部演示工具条展示主控、远端计算 Agent 与普通 Agent 三种使用模式。它位于 TaskPaw 壳外，明确标为设计预览；真实打包版依据已安装角色、明确启用状态及认证固定能力，不允许通过界面切换取得 Hub 权限。

普通 Agent 保持现有监控 / 任务日志 / 设置和手动“添加监控”，可继续只做字幕翻译。其界面没有影片工作区、审批、设备准入或领取操作，也不要求工作流硬件配对和模型准备。普通监控注册不等于工作流 enrollment；未明确启用时不下载 LTX、不自动领取影片，发现翻译服务不代表获准调用。原型的“添加监控”仅展示已有手动入口说明，不保存真实配置，也不将此机器加入五机工作流注册池。

迁往 Windows 的是完整 Hub 职责，包含所有机器的普通监控、工作流任务、历史、事件、日志与通知。工作流设备池仅是全机群中明确授权的子集；普通 Agent 仍可被 Hub 监控，不因出现在机群中而获得执行或 NAS 权限。迁移页须盘点全机群和既有通知关联，不能只迁五台计算节点。

## 一个默认投片目录

默认只需把影片复制到主控的一个普通本机文件夹，界面使用逻辑别名 INBOX。无需额外投递器、逐片提交或 ready 文件。主控自动观察与补扫，通过稳定检查、写占用检查、媒体探测和一致副本的整包校验后登记队列、分配计算设备；用户不需要按机器分别投片。每台 Agent 的 WORK-01…WORK-N 是受控暂存 / 工作目录，不能混称人工收件根。

图文确认里的原始来源统一展示“主控 / INBOX / 输入清单”，与远端工作副本、回传成品及正式 NAS 目标区分。未来可以登记多个投递入口或来源 owner，但这是可选扩展，不与计算设备数量绑定。上述检查建立可处理的一致快照，不声称证明外部复制工具已传完用户全部原件。此技术边界留在设计与折叠诊断里，不要求用户逐片接受风险声明。正常输入在成品取得 NAS 回执后，复核源身份、内容与成员仍一致即可自动清理；实际变化、仍在写入、身份未知才保留为待清理。

## 远端 Agent 界面

远端保留 Agent Console 的本机监控、任务日志与设置，补充资源与主控连接。默认显示本机领取影片、任务身份、LTX Encode / Denoise 当前阶段、原始计数 / 速率、阶段已用与剩余，以及独立运行 ETA；继续保留已有开发活动或服务监控。

远端只能查看 / 控制本机任务、暂停本机新领取、按本机权限停止受管任务、查看资源与日志、修复配对。界面没有全局影片审批、NAS 目标选择、正式片库管理或设备退休入口。主控离线 / 配对失效时设置与连接仍可访问；既有任务状态未知不能被“重连”或“重新配对”清除。

远端只安装 TaskPaw Agent、worker 与所需模型 / 字幕运行时，不安装 Miko / Filmpaw 主控组件。Mac 信息桥仍是独立只读桥，不属于远端 GPU Agent 模式。

## 影片状态与数据语义

初始演示集覆盖等待收件检查、待领取、Encode、Denoise、翻译、成品回传、Miko 完整后处理、演员匹配、待确认、多候选、无匹配、NAS 离线、写权限不足、同名冲突、入库未知、已入库待清理、完成和跳过。所有影片标题、演员和目录标签均为虚构。

初始配置中，5070 Ti 16 GB 与 5060 Ti 16 GB 优先领取 4K，空闲时可处理 1080p；三台 5060 8 GB 只允许 1080p。这是目标准入规则展示，不是性能实测结论。正在运行的任务不会因新片到达而被抢占。

LTX 只展示当前阶段百分比、原始计数和速率；Encode 使用 `frame/s`，Denoise 使用 `s/step`。详情区分阶段已用、阶段剩余和 LTX 本次运行剩余；后者不包含翻译、回传、刮削和入库。不将阶段 100% 合成为影片总体完成，也不将未观测到的阶段标为完成。原型是明确标识的静态快照，没有计时器伪造进度。

文件数量、翻译字幕条数、设备使用率各有自己的单位。阶段没有数据时显示状态或未知，不编造百分比。入库回执与来源清理结果分别记录。

五台不是固定上限。在线数量、注册数量、可新领取节点和可用容量从动态注册状态计算；有计算 owner、排空、离线、未配对 / 未核验、停用或执行未知的设备不计入可新领取容量。


## 设备添加、修改与准入

设备可增减，五机只是初始配置。添加表单至少包括名称、网络地址 / 主机名、Agent 网络端口、一次性配对信息、GPU 型号和显存、系统 RAM、受控工作目录、可用空间、请求的 1080p / 4K 能力。GPU 支持已知型号选择及自定义声明；未知型号不能仅凭名称或显存自动授权。

手工录入与节点探测结果分列展示，区分声明、已配对身份、硬件核验和已验证执行 profile。默认网络示例端口 5680；本机控制口 5681 不可当作 LAN 控制入口。修改地址、能力或工作目录后旧核验失效；编辑有在途或未知 owner 的设备须先排空和核对。

未联通、配对失败 / 失效、硬件不符、缺少适用 profile、工作区空间不足均不得加入可领取池。表单另设“仅登记待验证”，允许保存有效身份字段和硬件声明为 `pending_pairing / pending_validation` 候选；未探测时保留缺失，不把声明补成实测。该动作不启用领取，不授予执行凭据；之后仍须独立配对、探测、profile 核验和批准。

对比不一致时必须明确采纳或修正声明，再验证能力；不能通过勾选 4K 绕过 8 GB 限制。两台初始 16 GB 节点的 4K / 1080p、三台初始 8 GB 节点的 1080p 是演示基线；新增硬件需独立验证，既有 4090 / 5090 配置不是此次准入证明。保存候选后重新编辑，也不能把已保存的未核验声明当作可信硬件报告或已验证 profile。

所有设备总数、在线数、可领取数、可用容量和设备列表来自当前注册与生命周期状态。退休对象不计入当前池；未配对 / 未核验 / 停用 / 排空 / 离线 / 未知执行 / 已有计算 owner 均不计入可新领取节点。

## 排空、停用、重新配对与移除

“排空”先阻止新领取，在途任务继续。本机页、远端页、Hub 管理和工作区设备页共同读写同一设备 owner / 暂停状态：加载本机任务立即占用 owner；本机或远端暂停 / 停止后仍保持停止新领取，不能仅清除 owner 就重新计入可领取节点。

独立的“隔离 / 撤销新领取权限”允许在设备离线、仍有在途任务或执行未知时操作。它立即撤销未来领取权限，保留旧 owner、attempt、任务、回执、事件游标及 outbox 义务，不停止旧 GPU、不重派、不清理来源。本机隔离只影响本机 Agent，不关闭 Hub。

隔离后的重新连接只能通过受限、可审计的核对通道关联旧 attempt，不能恢复领取或消除 unknown。必须先取得核对证据收束旧 owner，再重新配对与核验资格；普通重连或“重新配对”按钮不能越过这个顺序。完整停用 / 退休仍须 owner 核销与排空，不能把独立撤销当作旧执行已经停止的证明。

“移除”使用“移除（保留历史）”或“退休”文案，且只能对无在途 / 未知任务、已排空、已停用并撤销凭据的节点执行。它让设备退出当前池，保留稳定设备身份及任务、事件、入库回执、来源清理记录、通知 outbox 的历史关联，不删除任何片源。当前主控本机不能通过普通远端设备退休流程消除唯一主控；迁移走明确的独立流程。

这些约束必须由后端事务和身份核销执行；前端禁用按钮只是解释，不是安全边界。原型中的“模拟任务完成 / 核对通过”只是固定场景切换，不是可用于生产绕过证据的按钮。

## 图文确认与来源清理

确认弹窗优先展示本次 Miko 最终封面、影片编号 / 分辨率、演员和最终 NAS / 库根 / 精确目标。最终文件包可展开，原始来源与详细证据折叠。主流程不展示技术风险声明，也没有逐片授权复选框。来源区域用“入库完成后自动清理本次收件来源”说明预设行为。

正常路径只有一次“确认入库”。点击本身产生明确授权，后台绑定影片版本、演员、目标、最终成品包 hash、封面版本和输入清单及身份；内容、封面、目标或清单变化必须撤销旧授权并再次确认。取消 checkbox 不取消这些绑定。原型只模拟回执与清理结果；真实实现不得由前端按钮自行生成成功证明。

收件检查尚未通过时显示“等待收件检查”，后台检查完成后自动进入处理，不要求用户额外提交。正常普通目录输入不再因为没有发送端完成证明而永久禁止清理。成功入库后，如果来源确有变化、仍写入、暂不可访问或身份不能确认，显示“已入库 · 待清理”与简短原因；只重试清理，不重新执行修复、后处理或上传。源内容 / 成员变化不能通过普通重试或“我已处理”绕过复核。

| 条件 | 界面行为 |
| --- | --- |
| 唯一有效目标、后台收件检查及最终成品检查通过 | 查看封面、演员和目标后，一次“确认入库”，后台完成归档与来源清理 |
| 收件检查待定 | 显示“等待收件检查”，不开放入库；检查通过后进入正常流程 |
| 多个演员 / 位置候选 | 初始无默认授权，明确选择后重新核对目标 |
| 无匹配 | 人工指定已有演员及合规库根，或转人工接管；不自动创建未知演员目录 |
| NAS 离线 / 权限不足 | 确认禁用并显示具体原因；恢复后重新预检与图文确认 |
| 同名包冲突 | 禁止覆盖；显示核对与接管入口，不能用“重试”覆盖已有片库 |
| 入库结果未知 | 先查持久回执与目标文件身份；核对前禁止重传和来源清理 |
| 已入库、来源被占用或断联 | 保持“已入库 · 待清理”，只重试清理，不重复修复 / 刮削 / 上传 |
| 输入身份发生变化 | 保留来源，阻止清理重试；转人工核对，不沿用旧授权 |

原始输入与处理后的成品包是两个 manifest。清理只包括授权清单内、仍具备原身份的文件；不能递归删除演员目录、影片父目录或后续新增文件。正式 NAS 库根及其别名、映射盘、重叠祖先 / 子路径始终排除在清理根之外。空目录和受控工作副本的清理由独立所有权策略处理，不能扩大原片授权。

跳过保留来源。对入库未知的任务，跳过不会伪造已核对成功；详情保留未知记录。人工接管展示输入与成品位置、保留原状态；原型“打开文件夹说明”只显示逻辑位置，不调用系统文件管理器。真实产品应在对应机器通过受限能力打开注册目录。

## Miko 最终产物与封面

修复与字幕结束后，每片都在私有工作区完成 Miko 完整后处理；已有 NFO 或封面不能跳过。复用 Miko 的元数据、文件整理、图片生成与标识规则，TaskPaw 不另造水印。展示的“破解”、中文字幕与分辨率标识来自真实阶段成果；字幕须验证语言及非空内容，无语音、空字幕或只存在 `.zh.srt` 文件不能据此标成中文字幕完成。旧图不能保留过期标识，更新与重试也不能重复叠加标识。

最终确认使用本次处理后的封面和文件包。需要目录封面的多视频 / 分卷包将 `folder.jpg` 明确列入包，字节须来自本次最终 poster，并随包版本、审批和 NAS 回执绑定；不能因逐片拆分丢失父目录语义。原型“星河慢行”展示适用的 `folder.jpg`，“未命名的岛”展示无语音且不含中文字幕标识的分支。图片缺失、标识不符或必需的 `folder.jpg` 缺失均阻止入库，进入简短原因及重试入口。所有刷新仅在私有工作区完成，不能覆盖 NAS 中已有封面。

## 主控后台组件与安装

TaskPaw 是唯一桌面入口。Miko 与 Filmpaw 的适配运行时仅由主控安装器负责安装、依赖隔离、版本核验、进程健康、升级与回滚，不要求用户再操作两个独立桌面主程序。Miko 负责每片完整后处理，Filmpaw 负责演员位置索引、安全归档与回执，编排和人工确认仍留在 TaskPaw。

保留普通 TaskPaw 使用；只有用户显式启用影片工作流后才选择主控或计算 Agent。工作流角色向导一次性完成目录配置、硬件配对、模型下载确认与预检，自动建立必要的执行配置和任务观测，无需手工添加 Jasna 或新 monitor。主控设置及远端连接页均说明这一流程，不另造一套监控添加步骤。既有“添加监控”保留用于手动任务；升级不会自动启用或启动旧任务。工作流执行与手动任务共享同一 GPU owner，避免同卡重复执行。

设置页明确主控组件与远端安装包的不同组成，以及后台服务和窗口生命周期。当前伴随进程模式必须经过预检和显式迁移，不能仅因界面新增工作区就假定关闭窗口不会停止现有服务。

## Mac 信息桥

只提供状态、事件和有限的脱敏日志；不显示派单、GPU 控制、终止任务或文件删除。初始快照过期 12 分钟，并展示事件序号缺口。模拟刷新只更新当前快照的新鲜度，不把历史缺口伪装成已经补齐。日志演示为 5 行，界面标明目标上限 200 行 / 64 KiB；这属于设计限制，不是已实现的传输能力。

使用语义化 button、label、select 和原生 dialog；主要控件至少 44px，壳外演示切换不属于生产权限。提供可见键盘焦点、跳至主体链接、模态焦点限制、Escape 关闭和焦点恢复。390px 卡片与设备表单改为单列，顶层页签换行；工作区九项导航收于独立导航弹窗。

遵循减少动态效果偏好，不自动更新影片进度、不自动播放。状态同时使用文字和颜色；LTX 只显示真实阶段单位与已知指标。主控连接健康、本地 API 健康、设备准入与 GPU owner 分开显示，不能用一个绿色圆点代表全部正常。

## 手动预览路径

1. 打开 V3，确认 TaskPaw 顶层机群 / 管理 / 事件 / 本机监控 / 设置仍在；进入影片工作流才出现九项内部导航。
2. 概览暂停新领取，在途任务继续；队列筛选 4K / 1080p，打开 Encode / Denoise 详情核对计数、速率和独立 ETA。
3. 待确认打开“星河慢行”，核对 Miko 最终封面、演员、NAS 目标及含 `folder.jpg` 的文件包，无需勾选，一次确认模拟入库及清理。“微光笔记”先显示等待收件检查，可在详情的演示场景里模拟检查及后续处理通过，再走同一确认路径。
4. 多候选须明确选择；无匹配须人工指定或接管。离线、权限和同名冲突不能盲目确认。
5. 异常中先核对“海风有声”的未知结果，再处理清理；对“长夏切片”模拟输入变化，再次重试仍被阻止。跳过或接管不移除未知核对义务。
6. 在顶层管理添加设备，修改地址、端口、GPU / 显存 / RAM / 工作目录及能力。分别体验离线、配对失效、硬件不符、自定义 profile 未验证、空间不足；未通过时不能加入领取池。手填 16 GB 不会改变独立探测 fixture 的 8 GB 实际报告。
7. 未验证型号可“仅登记待验证”，核对声明保留且无领取资格。正常添加后查看动态容量；空闲节点可排空 → 停用撤销 → 退休。在途或未知节点可先隔离撤销未来领取，但重连后仍须核对，不能直接退休。核对本机加载任务及远端暂停 / 停止后均不计入可新领取节点。
8. 在壳外切换远端 Agent，查看本机 LTX、资源、日志与连接；确认没有全局审批 / NAS 控件。失联再配对不会清除未知执行义务。
9. 主控设置查看 Miko / Filmpaw 的安装器托管范围；工作区设置查看一个中央 INBOX 与每机 WORK 的区别。
10. 缩至 390px，用键盘 Tab / Escape 操作导航、设备表单和确认弹窗。刷新或重置会清除所有模拟状态。
11. “月色剪影”详情可模拟最终封面缺失和后处理通过；已有 NFO 不跳过 Miko。待确认影片详情可模拟归档时来源变化，确认后保留“已入库 · 待清理”，不会重复上传。
