# 本机影片收件

收件器把主控本机的普通目录转换成可核验的工作副本。日常投递形式是
`<INBOX>/演员/影片/文件`；一个影片目录可以包含分卷、对应字幕和图片。
无需 ready 文件或逐片提交按钮。普通监控机器与计算 Agent 不启动收件器。

本实现提供显式构造的 `IntakeService` 和 `WorkflowStore` API。
生产服务生命周期由 T05 装配，界面由 T06 装配；仅安装当前模块或启动现有
Hub、Agent 不会自动启用影片工作流。配置没有默认媒体路径。

## 配置和发现

本机 operator 配置一个 enabled INBOX、一个不重叠的私有工作目录、明确的
intake component、影片策略和经过批准的处理 profile。两处目录均需核验实际
原生身份。本轮支持固定本机 NTFS 路径；通过 SMB 向其他机器共享这个本机目录
不改变本机收件方式。UNC、映射网络盘和 reparse 根不是本轮收件入口。

Windows 目录通知提示哪些来源需要复核；启动、事件溢出和定时补扫负责完整发现。
默认稳定时间 60 秒、补扫间隔 30 秒，每次只有一个快照 operation、一个 probe。
稳定时间按当前运行的 monotonic 时钟累计，重启重新计时。窗口内停止增长并不
等于外部复制已经结束，因此还要检查写占用、全部成员、完整内容 hash 和独立副本。

影片包默认最多 4096 个成员、深度 8；内存脏提示默认最多 256 个。当前根目录
前沿枚举最多 4096 个目录对象和 65536 个条目；超限保留已观察候选并显示补扫
未完成，不依据截断列表判断来源丢失。超限根的分页续扫尚未实现。

直接放在 INBOX 根的文件会使补扫未完成，应放在影片子目录中。
底层枚举原因是 `root_package_required`；当前服务摘要使用 `partial_observation`。
一级影片目录可以直接放视频或明确的 CD 子目录；混合无法明确归属的结构需要
人工处理。演员目录中的附件不会自动分配给所有影片。文件名和 NFO 只是分组
线索，目录及文件的原生身份才是去重依据。

## 状态和证据

| 状态 | 含义 |
|---|---|
| `receiving` | 文件仍写入、成员变动或只得到部分观察，等待复核 |
| `waiting_stability` | 完整观察已记录，等待本次运行的稳定窗口 |
| `snapshotting` | 唯一受管 operation 正在复制、hash 或顺序探测 |
| `operational_ready` | 当前来源 generation、完整副本和明确 profile 均通过，可供后续领取 |
| `needs_attention` | 归属歧义，或已归档来源变化需要核对 |
| `blocked` | 工具、媒体必要字段或经过批准的 profile 不足 |
| `waiting_capacity` | 工作目录容量不足 |
| `unknown_owner` | 进程、I/O 或原生句柄退出未被证明，保留 operation 与额度 |
| `missing` | 完整补扫没有发现当前来源包，历史仍保留 |

脱敏查询提供状态、固定原因、观察时间、最近完整补扫时间和 generation；私有绝对
路径仅限本地授权配置读取。媒体事实记录实际尺寸、帧率、像素比例、旋转、隔行、
选定流、版本与原始结果摘要。缺字段或 probe 失败不会退回假定 1080p。
本模块不内置 GPU 能力许可；profile 不足时可保留已核验快照，但不会发布可领取输入。

已知界限：一级影片目录删除最后一个视频、只剩图片或字幕时，当前结构分类可能将
仍存在的目录记录为 `missing`，剩余附件观察暂不刷新。目录身份和历史保留，视频
重新出现后可按同一原生身份重新发现。此项尚待修正，不构成删除许可。

## 副本、来源变化和恢复

快照使用 `<WORK>/intake/<operation-id>/` 的独占新目录。源对象和所有路径祖先
被持有到最终复核；工作副本独立写入、flush、全量读回并核对实际身份。固定 helper
通过受管 Windows Job 启动，每个 ffprobe 先暂停，主控记录其准确进程出生身份后
才允许执行。helper 没有数据库或自由命令执行入口。

完整快照及其所有影片在同一事务发布。提交失败可核对并重放同一结果，不能重复建片。
目录改名保留已确认的影片身份；同一路径换成另一原生目录形成新的收件记录。旧快照、
尝试、归档 receipt 和清理事实继续保留。

来源变化会使旧准入与批准失效。通知溢出、重启和未完成补扫另有持久根状态，补扫前
阻止新的领取、批准、归档和来源清理。已经发生的处理结果和外部 receipt 仍记录为事实。
停止操作先持久记录取消，再等待实际进程、I/O 和句柄关闭；线程等待超时不等于退出。
未收束的 owner、工作目录和配额交 T08 恢复核对，不通过新建空库或重开 operation 绕过。

本模块只读取 INBOX、写受控工作副本和工作流状态。完整 NAS receipt 后的精确来源
清理由 F02 执行，NAS 已有内容始终不属于本模块的删除或覆盖范围。

## 本地验证

`uv run pytest` 是项目测试入口。收件测试使用新建的临时 SQLite、NTFS 目录和
ffmpeg 生成的小视频；不会使用配置中的影片或 NAS。指定
`TASKPAW_INTAKE_FROZEN` 为本次构建的 backend EXE 时，原生 helper 测试还会验证
该实际二进制；缺该文件时 frozen 用例明确跳过，不代表已经通过。

源码或 frozen helper 的测试通过，只证明相应执行链；生产安装、整机服务装配、GPU
处理和 NAS 联调仍需各自验收。子任务按当前操作者要求使用本地 AFK 与唯一外审，
远端 CI 留到整套 EPIC 最终整合。
