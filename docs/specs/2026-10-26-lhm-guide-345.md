# #345 — 功耗 page: inline LibreHardwareMonitor install guide under a machine's sensor line

Date: 2026-10-26 · Base: `986e37c` (main, 3.11.0) · Branch: `afk/lhm-guide-345`
Planner: Claude (driver). Implementer: Claude Opus 5.5. Gate: Codex astra xhigh.

## Spec review

3.11.0's `SensorLine` (`taskpaw_v3/ui/src/components/power/SensorLine.tsx`) renders
`CPU / 风扇：LHM 未运行` when a machine reports sensors without LHM. The operator
wants the install steps right there, guided, instead of a dead sentence. The
confirmed V3 preview (artifact v3, row GPU-02) shows: a text-button link
`安装步骤` at the end of the line; clicking expands a guide block under the line
with a lead sentence naming the machine, three steps, two command blocks with
copy buttons, and a closing note.

Core need: one component, no settings, no backend, no new page.

## Acceptance criteria

- AC1 `SensorLine` gets a `machine: string` prop. When `sensors` is present and
  `sensors.source !== "lhm"`, the line ends with
  `<button type="button" className="guide-link" aria-expanded=…>安装步骤</button>`
  (text `收起安装步骤` while open). No button for `source === "lhm"` or when
  `sensors` is absent (old agent).
- AC2 Open state is local (`useState`), default closed. While open, a
  `<div className="m-guide">` is rendered as a sibling right after the
  `.m-sensors` div (the machine row is a CSS grid; `.m-guide` spans
  `grid-column: 1 / -1`). `SensorLine` therefore returns a fragment.
- AC3 Guide content, verbatim from the preview:
  - lead: `在 {machine} 上装一次 LibreHardwareMonitor，这一行就会显示 CPU 温度和风扇转速。`
  - three `<ol>` steps: `在 {machine} 上打开管理员 PowerShell，先跑第 1 段安装，再跑第 2 段设置。` /
    `第一次启动若弹出安装 PawnIO 驱动的提示，点同意。` /
    `它在 8085 端口提供只读的传感器读数（局域网内可见），TaskPaw 无需任何配置，Agent 下次采样即显示。`
  - command 1 (`1 · 安装`): `winget install --id LibreHardwareMonitor.LibreHardwareMonitor -e --accept-source-agreements`
  - command 2 (`2 · 设置并启动（写配置、开机自启、立即启动、打印读数验证）`): the
    setup script exactly as in the preview's second `<pre>` (search the WinGet
    package dir and Program Files for the exe, write `LibreHardwareMonitor.config`
    with the six keys; the exe search also covers WinGet's machine-scope
    portable directory `%ProgramFiles%\WinGet\Packages`), register the logon task `LibreHardwareMonitor` with
    highest privileges, start it, sleep 15, print the temperature/fan lines).
  - note: `只需做一次；TaskPaw 不会自动安装或远程推送。复制按钮不可用时，直接选中命令文本复制。`
  The two commands live as string constants in the new `LhmGuide.tsx`.
- AC4 Each command block has a `复制` button: `navigator.clipboard.writeText(text)`;
  on success the label reads `已复制` for 1.5 s; on rejection or when the API is
  missing, the `<pre>` text is selected (`Range` + `getSelection`).
- AC5 Styles in `powerStyles.ts`, scoped `.mw …`, per the preview:
  `.guide-link`, `.m-guide`, `.m-guide p/.lead/ol`, `.cmd`, `.cmd-head`, `pre`,
  `.copy`, `.note` (same hex values / tokens as the preview). `pre` scrolls
  horizontally inside the block (`overflow-x: auto; white-space: pre`).
- AC6 Tests in `taskpaw_v3/ui/src/test/sensors.test.tsx`: link present only in
  the no-LHM state (absent for `source: "lhm"` and for `sensors: null`); toggle
  shows the guide with the machine name in the lead sentence and both commands;
  copy calls a mocked `navigator.clipboard.writeText` with the exact command and
  the label changes to `已复制`; the fallback path selects text when `clipboard`
  is undefined. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` green.
- AC7 CHANGELOG entry under a new newest heading (no version bump here; the
  release bumps to 3.11.1).

- A1 The machine row `li.machine` is a grid with named areas; a full-width
  child uses `grid-column: 1 / -1` like `.m-sensors` does today (read:
  `powerStyles.ts`, `.mw .machine`, `.mw .m-sensors`).

## Key implementation notes

- Keep the preview's wording exactly; the machine name comes from the row
  (`m.name`), the same string the row's `<h3>` shows.
- `SETUP_CMD`: the preview's second `<pre>` has no backticks and no `${`, but it
  has **five backslashes** (`\Microsoft\WinGet\Packages`, `\LibreHardwareMonitor`,
  `\$env:USERNAME`). In a plain string or an ordinary template literal they
  vanish (`\M` → `M`, `\$` → `$`) and the script silently breaks (critic C4).
  Write both constants with `String.raw` template literals and literal
  newlines (no `\n` escapes), and decode the preview's `&lt;`/`&gt;` back to
  `<`/`>` (JSX text needs no entity escaping). Add a test that the setup
  command contains `\Microsoft\WinGet\Packages` and `"$env:USERDOMAIN\$env:USERNAME"` verbatim.
- Step 1 keeps the preview's markup: `在 <b>{machine}</b> 上打开<b>管理员</b> PowerShell，…`.
- `SensorLine.tsx` has no hook imports today; add `useState`.
- Colours: `powerStyles.ts` has no `--text-2`/`--label`/`--line-strong` tokens;
  use the file's hex literals as its neighbours do (`#d8e5f6`, `#b2c3d5`,
  `#34485b`), and keep `.m-guide { min-width: 0 }` so `pre` can scroll inside the
  grid (critic C1/C5).
- Tests: `sensors.test.tsx` fakes timers for every test, so the 1.5 s `已复制`
  reset needs `vi.advanceTimersByTimeAsync`; the clipboard promise needs
  `await act(async () => …)`. jsdom has no `navigator.clipboard`; follow
  `src/test/ffmpeg.test.tsx:46-47` (`Object.defineProperty(navigator, "clipboard", { configurable: true, get: () => undefined })` + `vi.spyOn(navigator, "clipboard", "get")`).
- The copy button's `onClick` must do the clipboard call inside the handler
  (user gesture); do not await before calling `writeText`.
