## SO_REUSEADDR vs a live listener — admitted P1 F1

The driver reran the experiment **outside the sandbox** on 2026-10-08 against
this tree on Darwin 27.0.0. This supersedes the earlier environment-blocked
conclusion about whether the hazard exists. Driver-reported evidence:

| Foreign listener | Its SO_REUSEADDR | `port_available(specific)` | Reuse claim and traffic |
|---|---|---|---|
| `0.0.0.0` | Off | True for `127.0.0.1` | DOUBLE LISTEN; new specific listener received the connection |
| `0.0.0.0` | On | True for `127.0.0.1` | DOUBLE LISTEN; new specific listener received the connection |
| `::` | Off | True for `::1` | DOUBLE LISTEN; new specific listener received the connection |
| `::` | On | True for `::1` | DOUBLE LISTEN; new specific listener received the connection |

The same-address control returned `port_available=False`. In all four wildcard
cases, the 3.9.10 baseline exclusive bind without SO_REUSEADDR refused with
errno 48, while a TCP connect to the specific address succeeded and was accepted
by the existing listener. Unconditional reuse therefore violates constitution
§3: `listen()` does not prevent wildcard/specific coexistence on this platform.
The previously distributed local **3.9.11 packages carry the unfixed behavior**;
their historical build, installation and same-address tests do not prove safety
against wildcard listeners. Windows never used this POSIX reuse path.

### Minimal correction and consumer effects

`claim_port` enables SO_REUSEADDR before its first bind + listen on Linux,
without a connect probe. Linux requires reuse on the old socket for TIME_WAIT
restart and rejects binds conflicting with a live listener. On other POSIX
platforms, it first attempts bind + listen without reuse. Only EADDRINUSE
triggers one data-less TCP connect to the same host/port, with a one-second socket
timeout and immediate close. Only ECONNREFUSED from that connect permits a fresh
socket to retry bind + listen with SO_REUSEADDR. A successful connection, timeout,
other error, or failure creating/configuring the probe preserves PortInUseError.
Non-conflict bind errors retain their existing diagnostics; failed exclusive,
probe and retry sockets are closed. No SO_REUSEPORT is used. Windows continues
to bind without reuse or a probe. Public signatures and call sites are unchanged.

Consumers enumerated before editing:

- `taskpaw_v3/agent/server/launcher.py`: `ensure_port_free` receives a conservative
  advisory result; `run_agent` claims its network/control sockets using the new
  guard. Existing cleanup on a failed second claim is unchanged.
- `taskpaw_v3/hub/server/app.py`: `run_hub` read/control claims gain the same guard;
  existing socket and database lease cleanup remains unchanged.
- `reclaim_ports_from_stale_instance` in `taskpaw_v3/core/net.py`: phase-one
  classification now rejects live foreign wildcard listeners before terminating
  any identified TaskPaw backend. On non-Linux POSIX, each unowned port check can
  add one probe.
- Both reclaim helpers' release-wait loops still poll `port_available` with a
  0.2-second sleep. A probe can occur per poll only while exclusive bind + listen
  fails with non-Linux POSIX EADDRINUSE. This is acceptable for a bounded startup
  wait: the connection carries no application data and closes immediately. Sleep is
  clamped to the remaining deadline so a slow probe adds at most one one-second
  TCP timeout beyond the deadline (plus scheduling overhead), including across
  the multiport helper's shared deadline. No caller arguments changed.

The probe is a point-in-time observation, not an atomic guarantee against a new
foreign listener appearing between connect refusal and reuse bind. Hostname
resolution, already possible in bind, is not bounded by the TCP socket timeout;
configured numeric LAN/loopback addresses avoid that resolver limitation.

### Linux CI regression — admitted P1 IR1

Required CI on `0f0a734` reported **1 failed, 4166 passed** in each Ubuntu
Python 3.10 and Python 3.12 job. Both failed
`taskpaw_v3/tests/test_net.py::test_immediate_restart_after_server_closes_connection`
at `assert port_available(*address)` returning False. F1's exclusive first
listener and its accepted connections lacked SO_REUSEADDR. Linux requires
reuse on the old socket as well as the replacement to bypass TIME_WAIT, so the
guarded retry still received EADDRINUSE. The repair branch's up-front POSIX
reuse had passed this Linux regression before F1.

IR1 restores SO_REUSEADDR before the first bind + listen only when
`sys.platform.startswith("linux")`, and makes no connect probe there. Linux
rejects conflicting live listeners even with SO_REUSEADDR; the real wildcard
tests remain enabled to verify that property. Non-Linux POSIX keeps F1's
exclusive-first, one-second data-less probe and ECONNREFUSED-only retry unchanged.
Windows keeps no reuse and no probe. Only `claim_port` runtime policy and the two
helper docstrings change; signatures, callers and reclaim logic are unchanged.

### Regression coverage and adjacent-code review

`taskpaw_v3/tests/test_net.py` asserts each platform's policy:

- Immediate restart after the server actively closes an accepted connection:
  unchanged TIME_WAIT acceptance on Linux and Darwin; Windows remains skipped.
- IPv4 and IPv6 wildcard listeners with reuse off/on: availability is False,
  claim raises PortInUseError, and the foreign listener still receives a client
  on Linux and Darwin. Linux asserts zero probe connections; other POSIX asserts
  exactly two data-less probes and drains both. IPv6 skips only for unavailable
  loopback support; sockets use OS-assigned ports and bounded connection waits.
- Successful first claim: no connect on any platform; reuse is enabled only on
  Linux and remains disabled on Darwin/Windows.
- Uncertain connect (timeout, permission, unreachable): unchanged fail-closed,
  two-probe, no-reuse and closure assertions on non-Linux POSIX; explicitly skipped
  on Linux/Windows because those platforms have no connect probe.
- Socket-free guarded-reuse error paths explicitly simulate Darwin or Windows,
  covering IPv6 target/family, EADDRNOTAVAIL, probe setup/connect errors, retry
  failures, caller ownership and closure without depending on the host platform.
- New socket-free Linux cases assert reuse before bind/listen, no probe or retry
  even on EADDRINUSE, error causes, closure on option/bind/listen failures and
  caller ownership on success. These run on every CI platform.
- Existing fake-clock reclaim deadline assertions remain unchanged.

Search of `taskpaw_v3/src-tauri/src/*.rs` found no socket reuse, listener bind, or
independent port-availability check. The shell handles backend startup results;
it does not duplicate this path. Repository-wide source search found no other
production SO_REUSEADDR / SO_REUSEPORT or duplicate availability implementation;
Agent's advisory wrapper delegates to this helper. No Rust changes or separate
same-path Rust defect were found.
