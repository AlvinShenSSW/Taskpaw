## 2. API changes (control API, loopback, control token)

- `GET /control/setup` → `{status, step, role}`; `PUT /control/setup {step, role}` (forward-only state machine, else 422); `POST /control/setup/complete` (needs role; for 工作机 a confirmed identity).
- `GET /control/network` → `{lan_access, bind_host, bind_port, control_port, addresses[{ip,nic,primary}], address_changed_from, token_set, api_token_hint, firewall{platform, rule: present|absent|unknown, profile}}`.
- `POST /control/network/token {action: generate|reveal}` → `{token}`.
- `POST /control/network/firewall` → `{result: added|declined|failed|unsupported|timeout|pending}` (bounded overall at 120 s, UAC prompt included; `pending` = an earlier prompt is still open).
- `GET /control/workflow/detect` → `{gpu, tools{ffprobe,jasna,whisperjav,miko}, suggested{inbox,data_dir,staging}}` (cached 60 s; `?refresh=1`).
- `POST /control/workflow/settings/directory/inspect {path}` → `{exists, free_bytes, volume, local}` (POST keeps the path out of access logs).
- `GET /control/workflow/settings` adds `media_supported` (false off Windows); `PUT` refuses role controller/worker off Windows with 422 `{role: 「媒体工作流仅支持 Windows」}` (§12 OD-W).
- `PUT /control/workflow/settings` also takes `create_dirs: ["inbox_root"|"data_dir"|"staging_dir"]` — suggested folders made only after the rest of the save validated (§12 IR10).
- `GET /control/restart` → `{required, fields[], blocked}`; `POST /control/restart {boot_id}` → 202, or 409 `restart_busy`/`operation_busy`/`restarting`.
- `AgentConfig.lan_access: bool = False`.
- Hub: `GET/PUT /config/settings` (saved, running, restart_required, token masked, `controller_server_id`), `POST /config/openclaw/test`, `POST /restart`; `HubConfig.status_md_path`, `lan_access`.

## 3. Restart design

- **Backend:** `POST /control/restart` takes the settings admission lock; refuses when another save holds it (`operation_busy`), when `gpu_lease.holder()` is set (「本机正在运行：{label}」), or when a worker's `worker_busy(...)` is true. Remote work, queued films and crash-safe stages don't block. A grant closes the GPU lease in the same step as its busy check and marks the agent restarting under the lock: later saves, monitor changes, GPU admissions and a second POST get 409 `restarting` 「正在重启」 (§12 IR5). Success → 202, then `shutdown.shutdown()`, and `service.main` returns **exit code 75**. Hub likewise (only a concurrent save blocks; restarting refuses later saves and restarts).
- **Shell:** a watcher thread looks at the owned child every 250 ms — on Unix with `waitid(WNOWAIT)`, never reaping it, so the old process group is killed while its leader still pins the id (§12 IR6); Windows `try_wait()`. Exit 75 → drop the old Job / kill the old group (stragglers die), reap, respawn the same command, assign a new Job, read readiness (30 s; failure → existing startup-error path), load the new descriptor, rebuild the `main` window with the new init script at the old window's size, position and maximized state (§12 IR9; destroy, not close, so the close confirmation doesn't fire). Other exit codes as today.
- `init_script` adds `restart: true`; the UI offers the button only when it sees that flag. No new IPC permission; capabilities unchanged.
- **UI:** overlay 「正在重启 TaskPaw…」 (a labelled `aria-modal` alertdialog that takes the focus); if the window isn't replaced after 75 s (≥ the old backend's 5 s stop + 30 s readiness + the rebuild, §12 IR8) → 「重启失败，请退出并重新打开 TaskPaw」.

## 4. Firewall design

Fixed backend route `taskpaw-backend agent-firewall allow --ports P[,P]` — frozen builds on Windows only, integer ports 1–65535, at most 2. It runs `%SystemRoot%\System32\netsh.exe advfirewall firewall delete rule name="TaskPaw Agent"` then `add rule name="TaskPaw Agent" dir=in action=allow protocol=TCP localport=P profile=private program="<backend exe>"`. Started via `ShellExecuteExW("runas", SW_HIDE)` on a worker thread, owned by the TaskPaw shell's foreground window (so the prompt comes to the front); the whole request — prompt included — is bounded at 120 s (`timeout`), one at a time (`pending`); error 1223 = declined (§12 IR3). One UAC prompt under the TaskPaw publisher. Status read without elevation via one fixed `powershell -NoProfile -NonInteractive` call (UTF-8 output; `Get-NetFirewallRule` / the `Get-NetConnectionProfile` of the adapter that owns `bind_host` → JSON; not localised; the address enters the script only as a validated IPv4 literal), 8 s timeout, cached 30 s per address (§12 IR7).

## 5. Detection rules

Every probe: fixed argv, `CREATE_NO_WINDOW`, stdin null, timeout, kill the whole tree on timeout and again after the probe exits (POSIX: the process group; Windows: a Job object; §12 CX6), ≤ 4 KB kept — the rest drained in bounded reads — parsed by regex, nothing logged; network paths never probed, and PATH lookups (`local_which`) skip UNC / mapped-drive directories (§12 CX3, IR12).
- **ffprobe:** saved path → PATH (local directories only) → `ffmpeg.bundled_ffmpeg_dir(whisperjav)` of the WhisperJAV found in the same pass, else the saved one (§12 CX2); version from `-version` (3 s). The only tool binary ever executed.
- **Jasna:** saved path → monitor configs (`jasna_exe_path`) → `C:\Jasna\jasna.exe`, `%ProgramFiles%\Jasna`, `%LOCALAPPDATA%\Programs\Jasna` → `which("jasna")`; version from the PE file-version resource only (never executed), else 「已找到」.
- **WhisperJAV:** saved path → monitor configs → `C:\WhisperJAV\Scripts\whisperjav.exe`, `%LOCALAPPDATA%\Programs\WhisperJAV\Scripts` → PATH; existence only.
- **Miko:** root containing `mdcx/cmd/postprocess_one.py` in saved root, `<data_dir>\engines\MDCX304`, `<config_dir>\engines\MDCX304`; Python `<root>\.venv\Scripts\python.exe`; profile `%APPDATA%\com.mdcx.desktop\config.json` → 三项齐全 / partial / off.
- **GPU:** `LocalGpu`'s nvidia-smi query + `driver_version,power.limit` (5 s).
- **Windows only (§12 OD-W):** off Windows nothing is probed or suggested (no GPU, every tool not found, Miko off). Windows-only paths (netsh, PowerShell, the `C:\` / `%ProgramFiles%` candidates, drive-letter suggestions) are built with `ntpath` / `PureWindowsPath`, so their values are the same on every OS.
- **Directory suggestions:** fixed local drive with most free space → `TaskpawInbox`, `TaskpawWork`, `TaskpawStaging`. A suggested directory is created by the step's save (`create_dirs`) only after the rest of it validated (§12 IR10); a typed path is never created silently. **D5:** 「本地 NVMe」 → 「本地磁盘」.

## 6. Wizard state machine

普通 Agent `role → network → done`; 主控 `role → network → controller → done`; 工作机 `role → network → worker_fields → worker_join → done`. Each 下一步 saves the step's settings through the real writers, then the step to `agent.setup.json`. 上一步/修改 go back losslessly. After any restart (quit, crash, planned 3a) the wizard resumes at the saved step, re-reading the form from the saved config. Changing the role re-saves the workflow under the P2-4 guards.

## 7. UI per board

`views/SetupWizard.tsx` + one file per step; 4-step stepper (3 for 普通 Agent); states per step: loading, detected, missing, field errors, saving, refused. Settings-Workflow: section nav, RestartBanner, detection rows. Hub-Settings: `components/HubSettings.tsx` in `Settings role="hub"`. Fixtures at 390 px for every board.

- Rust: `restart_supervisor` unit with fake child + spawner — exit 75 respawns once and rebuilds; other exits do nothing; failed respawn readiness → `fatal_startup`; Job reassigned on Windows; `init_script` carries `restart`.
- Event-driven tests and injected clocks only; no host disk/wall-clock dependence.

## 9. Out of scope

Linux; headless-service restarts; draining/forcing a restart while busy; a Hub first-run wizard; re-running the wizard from settings; macOS firewall automation; DHCP reservation; multi-NIC binding; developer `scripts/setup-*` (only the final hint changes to 「打开 TaskPaw → 设置」).

## 10. Risks

1. A saved setting that cannot start leaves no UI — mitigated by the save-time bind/port probe, self-heal, existing startup dialogs.
2. IP change breaks Hub/worker addresses — copy recommends a DHCP reservation.
3. Program-scoped firewall rule goes stale if the install folder moves — status shows it; 重试 re-adds.
4. Reveal sends the token to the local UI — loopback + control-token gated, `no-store`.
5. Window rebuild loses in-page state — wizard resumes from disk.

### Code facts behind the contract
`startup_code` sends `initialization_required` only with no state and no fault file; the shell shows `Action::Initialize.confirmation()` and `recover_once` allows one restart. No restart command exists (`generate_handler![set_ui_lang]` only); on Windows `terminate_child` hard-kills after 5 s. `init_script` fixes the control token for the window's life and `api.ts` deletes it after reading, so a restart needs a new window. `guard_bind_exposure` refuses wildcard binds and requires a token for any non-loopback bind. `power` is live; `host_metrics` and `workflow` are not. Worker `join` returns 409 unless the running role is worker; a controller 401 doesn't say why. The Hub has no hub.yaml writer; `openclaw_enabled`/`openclaw_token` are already live store overrides; `openclaw_url` is fixed at Poller construction.
